Hackers Just Hijacked 10 Trusted Code Libraries. Their New Command Center Lives on the Ethereum Blockchain — Where No One Can Take It Offline.

On November 4, security researchers at Sonatype caught attackers hiding inside ten hijacked, previously-trusted packages on npm — the free, open-source building blocks sitting inside an estimated 97% of commercial software. Their trick wasn't a smarter virus. It was moving the control panel onto the Ethereum blockchain: public infrastructure that no company, court, or government can switch off.

Key takeaway Sonatype's Research Labs found a malicious loader — tracked as sonatype-2026-010515 and nicknamed "PolinRider" — appended to 12 releases across 10 hijacked npm packages. Instead of calling a server defenders could seize, it reads the latest outbound transaction from a specific Ethereum wallet, decodes a command-server address hidden in that transaction's bytes, and fetches its next payload from there. Block that address, and the attacker just sends a new transaction — cost: a few cents — and every infected machine finds it automatically on its next check-in. Researchers have tied earlier versions of this technique to North Korea-linked operations, though that attribution for this specific wave remains Sonatype's working assessment, not a settled fact.

The plain version

Almost no software is built entirely from scratch anymore. Developers pull in free, open-source building blocks — small packages that handle routine jobs like formatting dates or parsing files — and stack thousands of them together. By one widely cited industry audit, open-source code makes up roughly 97% of the average commercial codebase. Nobody reads all of it line by line; you mostly just trust that whoever maintains a package is who they claim to be.

That trust is exactly what a hacking campaign is exploiting. On November 4, researchers at security firm Sonatype found that attackers had quietly taken over the accounts behind ten previously-trusted code libraries on npm, the biggest catalog for JavaScript, and slipped a malicious loader into new versions — the kind of update millions of projects pull in automatically, often without anyone noticing.

Here's the clever part. Malware normally has to "phone home" to a server to get its next instructions, and that server is also its weak point: security teams or law enforcement can take it offline, and the whole operation goes dark. This loader skips that risk. Instead, it checks a specific Ethereum wallet's most recent transaction, decodes a hidden address buried inside it, and uses that to find its real command server.

Why does that matter? Ethereum is a public ledger that no single company or government owns or can switch off. If defenders block today's server, the attackers just send a new transaction — costing them pennies — and every infected computer finds the new instructions automatically, the next time it checks in. There's no office to raid, no company to subpoena, no domain to seize. The hiding place is permanent public infrastructure, repurposed as an unkillable mailbox.

The expert version

The npm registry hosts well over three million JavaScript packages, and Synopsys/Black Duck's 2025 OSSRA report puts open-source code in roughly 97% of commercial codebases, with a majority of the average codebase's files originating upstream. That breadth is the attack surface: a maintainer-account takeover on even a lightly-watched package can reach every downstream project that auto-pulls a semver-range update.

On November 3–4, 2026, Sonatype's Research Labs identified a loader it tracks as sonatype-2026-010515, nicknamed "PolinRider," appended to 12 malicious releases across 10 hijacked, previously legitimate npm packages — several of which had gone years without an update, the low-scrutiny maintainer profile attackers favor. OX Security independently corroborated the find.

The mechanism is a blockchain dead-drop, a pattern researchers call EtherHiding (or, in its zero-value-transfer variant, NullReceiver). Rather than hardcoding a C2 domain or IP — both seizable — the loader queries public Ethereum RPC endpoints, with a Blockscout API fallback for redundancy, to read the latest outbound transaction from a specific wallet (address 0x1eef0849eda15d87f64e51c73c8442cf3c8bcef3, also logged independently by GitGuardian in late October). It decodes a destination IP from that transaction's recipient-address bytes and fetches an obfuscated next-stage payload from it.

The operational payoff is censorship-resistance: Ethereum has no registrar, no hosting provider, and no administrator who can null-route an address. Relocating infrastructure costs the attacker a single on-chain transaction — a few cents in gas — read automatically by every infected host at its next check-in, with no coordinated re-infection required. Sonatype ties this loader to earlier May and August 2026 campaigns using the same wallet dead-drop pattern, and researchers — including Google's Threat Intelligence Group, on related EtherHiding cases — link the broader technique to North Korea-linked operations, though attribution for this specific November wave remains an assessment in progress rather than a confirmed finding.

Why it matters for tech + supply chain: open-source packages are the raw material of almost all modern software, and a control server that lives on a public blockchain can't be seized, blocked, or taken down the way a server can.

Why it matters for tech + supply chain: dependency trust is the softest point in the modern software supply chain, and a C2 architecture with no seizable domain or IP shifts the economics of takedown permanently in the attacker's favor.
